# EInvGstAddon – Phase 1: SAP Business One (Vipra) → ERPNext (VCPL) invoice synchronisation

Direct integration, no portal and no middleware:

```
SAP B1 10.0 (Vipra DB) --UI API + DI API--> EInvGstAddon (C#, .NET Framework 4.8, x64) --HTTPS REST (token auth)--> ERPNext 15 / company "Vipra Closures Private Limited" (VCPL)
```

Every A/R Invoice that is **successfully added** in SAP is created in ERPNext as a **Draft** Sales Invoice for VCPL.
Customers, addresses, contacts, items, UOMs, item groups and warehouses are created automatically when missing.
Phase 1 never submits an invoice and never calls any e-Invoice / e-Way Bill method.

## Solution layout (`EInvGstAddon.sln`)

| Project | Purpose |
|---|---|
| `EInvGstAddon` | WinExe entry point (started by SAP B1 with the connection string) |
| `EInvGstAddon.UI` | UI API: menu, screens, event wiring (`FormDataEvent` on object 13), recovery timer |

| `EInvGstAddon.Core` | DTOs, interfaces, `SapReader` (read-only SELECTs), in-memory store |
| `EInvGstAddon.ERPNext` | REST client, custom-field setup, customer/item/warehouse/invoice sync, `SyncEngine`, background `SyncQueue` |

| `EInvGstAddon.Tests` | 16 offline tests (fake ERPNext) + opt-in live tests |

Build: `MSBuild.exe EInvGstAddon.sln -restore` (Visual Studio MSBuild – the SAP COM interops are generated by `tlbimp` from the installed type libraries, which `dotnet build` cannot do). Tests: `dotnet test src/EInvGstAddon.Tests`.

## What happens when an invoice is added

1. `FormDataEvent` (object 13, `et_FORM_DATA_ADD`, **after** action, `ActionSuccess = true`) – ignored for any other company database than the configured one (`Vipra`).
2. The handler returns immediately; on the UI thread a `Pending` row is written to `@EINV_SYNC` (never lost) and the DocEntry is queued.
3. A background worker (never the SAP UI thread) runs `SyncEngine.Process`:
   1. read invoice, partner, items, warehouses from SAP (read-only SELECTs through the DI Recordset);
   2. **idempotency check**: query ERPNext for `custom_sap_sync_reference = Vipra-13-<DocEntry>` in company VCPL – if found, link it, never create another;
   3. ensure customer (UDT mapping → ERPNext custom field `custom_sap_card_code` → create) + billing/shipping Address + Contact;
   4. ensure items (`item_code` = SAP ItemCode; existing items reused unchanged), UOMs, item groups, warehouses (VCPL only; ownership validated);
   5. build the Draft Sales Invoice (exact SAP CGST/SGST/IGST/freight amounts as `Actual` tax rows on VCPL accounts) and POST it;
   6. write result to `@EINV_SYNC` and the invoice UDFs `U_ERPNextDoc`, `U_ERPNextStatus`, `U_LastSync`, `U_SyncError` through the DI API (never SQL); show the status-bar message.
4. ERPNext down / timeout → `Pending` with exponential back-off (30 s … 15 min, `MaxAutoRetries`), then `Retry Required`. A timeout after a POST is resolved by step 2 on the next attempt. Validation / configuration errors → `Failed` with the exact reason; **Retry** is available in the Pending/Failed screens and always re-checks ERPNext first.

Invoices created before the add-on's first start are not synchronised automatically (baseline `SyncStartDocEntry` is set to "next invoice"); any historic invoice can be pushed from *Invoice Synchronization → Synchronise Invoice*.

## Safety rules enforced in code

* Target company must not be Tint Tech Coatings / `TTCPL` (`AppConfig.ValidateTarget`, also blocked in Settings save).
* `ErpClient` exposes no delete; any write whose payload `company` differs from the configured company, or that mentions `TTCPL`, is refused before sending.
* Tax / freight / round-off accounts and warehouses must belong to the configured company, otherwise the sync stops with a clear message.
* Unmapped non-zero SAP tax types (e.g. TCS = type 7) stop the sync – nothing is created with wrong tax. Nothing is invented (HSN, GSTIN, PAN, accounts).
* API secret is DPAPI-encrypted per Windows user in `%LOCALAPPDATA%\EInvGstAddon\config.json`, masked in logs, never in source control.

## ERPNext setup (done on the Frappe Cloud site, additive only)

* Custom fields (created by *Create ERPNext Fields* / `ErpSchema`): Sales Invoice `custom_sap_database`, `custom_sap_docentry`, `custom_sap_docnum`, `custom_sap_object_type`, `custom_sap_sync_reference`; Sales Invoice Item `custom_sap_line_num`, `custom_sap_tax_code`; Customer `custom_sap_database`, `custom_sap_card_code`; Item `custom_sap_database`, `custom_sap_item_code`.
* Naming series `VCPL-SINV-.YYYY.-.#####` appended to the Sales Invoice series options (the site only had TTCPL series).
* Company `Vipra Closures Private Limited` (VCPL) – created from the Vipra SAP company; **no GSTIN configured**, so GST place-of-supply fields are not set and every draft carries a "GST configuration incomplete" warning.
* Server-side uniqueness: the reference field is indexed and checked before every insert; a database-level unique constraint would need a small Frappe app (`sap_b1_direct_integration`) deployed through Frappe Cloud – planned for Phase 2.

## Deployment on the SAP client

1. Build Release; copy `src/EInvGstAddon/bin/Release/net48/*` to e.g. `C:\Program Files\EInvGstAddon\`.
2. Register `EInvGstAddon.exe` in SAP B1 *Administration → Add-Ons → Add-On Administration* (or start it with the SAP-supplied connection string for a trial).
3. Log in to the **Vipra** company. Menu *Modules → E-Invoice & ERPNext Integration → ERPNext Connection Settings*: enter URL, API key, API secret, click *Create SAP UDF/UDT* (needs a SAP user with DI authorisation to create UDFs/UDTs), *Test Connection*, *Test Authentication*, *Save Configuration*.
4. Optional: *Warehouse Mapping → Auto-map SAP Warehouses* creates/links the 7 SAP warehouses under VCPL.

## Known issues / decisions needed

* **Rate precision**: ERPNext holds rates to 2 decimals (SAP: `0.0151`). The add-on keeps totals equal to SAP by adding the difference on `Rounded Off - VCPL` and notes the true SAP price in the line description, but line rates/net total then differ from SAP. Proper fix: raise rate precision in ERPNext (Customize Form / System Settings) – shared with TTCPL, so not done without approval.
* **Test drafts `T/SD/2243-2245/25-26`** were created before the VCPL series existed: they consumed three numbers of TTCPL's series and have pre-fix totals. They are Drafts in VCPL; delete them in ERPNext when convenient (the add-on never deletes).
* TCS (SAP tax type 7) needs a VCPL account, then add it to `TaxAccountMap`.
* Payment terms without a matching ERPNext Payment Terms Template are only reported (due date is still set from SAP).
* Service invoices (no item lines) are rejected in Phase 1.
